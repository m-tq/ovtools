Runbook & safety one column per program - what it does, what is safe, what takes time

Deploy fresh node

  • Use it for: a brand-new VPS that should become an Octra node.
  • It prepares the machine, builds the node, creates a new wallet and syncs the chain.
  • When the node is up it asks for the top-up and the bond amount; after you press Enroll the console tells you the epoch the chain scheduled and keeps watching - yellow, not red - until the node is an active validator and voting. A popup appears by itself the moment that happens, even if the run is already over.
  • Your only input is the host and its login. Swap size is the one setting you may change.
  • The monitoring dashboard is not part of a deploy: publish it later from Manage active node - Deploy monitor.
  • Takes: roughly 45-100 minutes; the chain sync is the slow part.
  • The machine must be empty - if a node already runs there, use Migrate.

Migrate node

  • Use it for: moving the validator that already runs to a new machine.
  • It copies the wallet and the chain first, and only then stops the old node - so the downtime is short.
  • The old machine stays powered off afterwards: keep it as the fallback.
  • The run ends by watching the chain admit the migrated validator: yellow while it waits, and a popup when it starts voting.
  • Takes: about 30-60 minutes; the validator is offline only for the final catch-up.
  • Never start the old node again while the new one is running - two copies of one wallet is the one thing that must not happen.

Manage active node

  • Use it for: the validator that is already running - increasing its bond, leaving the set, updating its software or putting the monitor online.
  • Increase bond adds OCT to the stake; the console asks for the amount (whole OCT) in a popup. Ask for a new increase only after the previous one is confirmed (the console handles that for you).
  • Exit validator leaves the validator set and waits until the stake comes back to the wallet. It can take a while - the network releases the stake on its own schedule. The node itself is not deleted.
  • Both need the node to be the active validator, so press Check first.
  • Node stuck in "ready / outside set"? Diagnose node shows why (pm2, RPC, head frozen, epochs behind, the rejoin verdict, memory), then Fix stuck node runs the bounded repair - pm2 restart / session, catch-up wait, rejoin, readiness. It signs no bond and never exits, and neither button needs a passing Check: a broken node cannot pass one.
  • Optional: Deploy monitor puts the read-only live dashboard online (graphs, logs, wallet, consensus) - the manage actions behind it live in this tab, not on the dashboard. The popup asks for the host name and how to get the certificate - your own Cloudflare origin files, or an automatic Let's Encrypt one (the host name must already point at the machine).
  • Update node (same section) updates the software when the developer announces a release (upstream README: "How to update (if you are already a validator)"): controls/upgrade.sh is run in test mode first - it changes nothing - and only then with --apply (pull, build, restart, wait, verify). Its own verdict tells you it worked: validator_active or observer_synced.
  • If that tool cannot run, Manual update does what the README lists by hand: git pull, check, build mcl, dune build, stop, run.sh --rebind-runtime, stat.
  • Prune preserved states drops the states of the previous epochs (storage.sh --prune-prior --yes) to free disk; the daily prune job does it too.
  • An update never runs a sync, never changes config/network.env and never re-enrolls: the identity and the data stay. The node is offline only for the restart.

The console only talks to the hosts you type; nothing is stored in the browser. Green means done, yellow is a normal wait, red needs your attention.

Increase bond

Adds OCT to the stake of the validator running on -. The node signs the transaction itself (bond_inc.sh as the octra user); the first increase runs plain, every later one is a new increase (--new) and is only allowed once the previous one is confirmed.

Exit validator

This takes - out of the validator set and starts the exit. The console:

  • submits the exit transaction (the node stops voting),
  • reports the epoch the chain recorded the exit at and the epoch the stake unlocks at,
  • leaves the withdrawal to this host (a timer retries it every 15 minutes) and reports again when the funds are back.

The unbonding period decides how long that takes (often a day or more), so nothing has to be watched or re-run: the node itself is not deleted and the wallet stays valid.

Deploy monitor

Publishes nginx + octra-dashboard on - as a read-only monitor: graphs, logs, wallet and consensus. The manage actions stay in this tab - the public dashboard carries no button and no token.

Ready for enrollment

The node is built, started and verified - its wallet exists and is online as an observer. Enrolling spends the bond from that wallet, so:

  1. send OCTRA to the wallet address below (at least the amount you enter),
  2. tick the confirmation when the transfer is done,
  3. press Enroll - the console then runs enroll - promote - verify and keeps watching the chain: the set fold admits the validator and it starts voting by itself. You get a popup the moment that happens, even if the run has already ended.
